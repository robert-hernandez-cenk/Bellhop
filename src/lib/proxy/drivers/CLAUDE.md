# Reverse-proxy drivers

Per-driver detail for the shipped drivers (plus `convert-caddyfile`). The interface, `getDriver`/`driverDeps`, the `none` driver, `checkCapabilities`, and `fileDriver` are in `src/lib/proxy/CLAUDE.md`.

Shared rules:

- Backend scheme (Caddy's rule): `https://` unverified when `insecureTls`; `https://` verified on port 443; else `http://`.
- `X-Forwarded-Port` is always `ctx.externalPort` (443), for backends building absolute URLs (#91).
- Forward-auth passes five identity headers: username, groups, email, name, uid (no `entitlements`).
- `ctx.outpost` is read only for `'forward'` routes; `buildRoutes` throws its missing-authentik error before producing one without an outpost.

## Caddy certificate modes (`proxyCaddyTls`)

`caddy` and `caddy-api` read it as `ctx.caddyTls` (inert elsewhere):

- `cloudflare` (default; unset is byte-identical to the original): Cloudflare DNS-01, fixed `ACME_DNS_RESOLVERS`; Caddyfile clause `CLOUDFLARE_TLS_BLOCK`.
- `letsencrypt`: Caddy's automatic HTTPS, no DNS provider; no clause.
- `internal`: Caddy's self-signed CA; `tls internal`.
- `files`: shared `proxyTlsCertificate`/`proxyTlsKey` pair (`ctx.tls`) nginx also reads; `tls <cert> <key>`.

Both drivers' `acmeDns01ViaCloudflare` is `caddyAcmeDns01ViaCloudflare` (`caddyTlsMode(inventory) === 'cloudflare'`, from `caddy.ts`): `prune-acme-challenges` runs only in `cloudflare` mode.

## Caddy driver (`caddy.ts`)

Default; `fileDriver`-based. `authModes: ['forward', 'oidc']`, `acmeDns01ViaCloudflare: caddyAcmeDns01ViaCloudflare`, `defaultConfigPath: '/etc/caddy/Caddyfile'`, validate `caddy validate --adapter caddyfile --config <path>`, reload `systemctl reload caddy`. `'managed-section'` file: content outside the markers is untouched; appended when no marker exists yet.

`render()` must stay byte-identical to the original generator: `unauthenticatedPaths` come from the raw stored strings in stored order, never rebuilt from `PathPattern[]`.

- One site block per host, guest, or external site (`ExternalSiteSchema`, `src/lib/inventory.ts`: a non-Proxmox target such as a NAS, never SSH/exec'd); hostnames comma-joined, canonical first.
- `tlsClause(ctx)` adds the mode's clause to every block; `files` paths are quoted by `caddyfileToken` when they hold whitespace, `"` or `\`, escaping only `"` (Caddy's only escape in a quoted token).
- Block-form `reverse_proxy` with unconditional `header_up X-Forwarded-Port 443` (`EXTERNAL_PORT`); `insecureTls: true` adds `transport http { tls_insecure_skip_verify }`.
- Forward-gated with exempt paths: `forward_auth` inside `@auth_required { not path <patterns...> }`, omitted when empty. `handle /outpost.goauthentik.io/*` routes outpost traffic regardless of exemptions.
- `'oidc'` routes get no `forward_auth`/`@auth_required`/outpost passthrough.

Exports `OUTPOST_AUTH_URI`/`OUTPOST_PATH_PREFIX`/`AUTHENTIK_COPY_HEADERS`/`CLOUDFLARE_TOKEN_PLACEHOLDER`/`ACME_DNS_RESOLVERS` for the admin-API driver.

Single-operator assumption: in `cloudflare` mode only, fixed `ACME_DNS_RESOLVERS`, one domain, one DNS provider (`CLOUDFLARE_TLS_BLOCK`).

## nginx driver (`nginx.ts`)

`fileDriver`-based. `authModes: ['forward', 'oidc']`, `acmeDns01ViaCloudflare: () => false`, `label: 'nginx'`, `defaultConfigPath: '/etc/nginx/conf.d/bellhop.conf'`, `statusPage: { suggestedPath: '/var/www/html/index.html' }` (Debian/Ubuntu docroot, served by the operator's own block), `usesSharedCertificate: true`, a `configPathNote` (whole file replaced, foreign file refused), validate `nginx -t`, reload `systemctl reload nginx`.

Shared `renderServerBody` (`src/lib/proxy/nginx-locations.ts`) renders everything from the `map` blocks to the last `location`, so NPM's `advanced_config` can't drift.

**Ownership.** `'owned'`, replaced whole; the "generated by Bellhop, do not edit" header is its `ownedHeader`, so `buildFileDriverScript` refuses before any backup/write (non-zero exit, naming the path and the `set-config proxyConfigPath` fix) a file with any other first line. `proxyConfigPath` is shared across drivers; a leftover Caddyfile would otherwise be replaced while `nginx -t` passed.

**File shape.**

- Two `map` blocks, always emitted, even with zero routes: `$bellhop_connection_upgrade` (WebSocket `Upgrade` -> `upgrade`, else `''`, like Caddy's passthrough) and `$bellhop_http_host` (Authentik's `$ak_http_host`: `$http_host`, else `$host`, keeping an explicit port). Prefixed because `map` names are global (duplicates fail `nginx -t`).
- Per route a `server`: `listen 443 ssl;` + `listen [::]:443 ssl;` (no `http2`, whose directive varies by release, and no port-80 server: both left to the operator), `server_name` = `route.hostnames` canonical-first, double-quoted `ssl_certificate`/`ssl_certificate_key` from `ctx.tls`, `client_max_body_size 0;`, `proxy_buffering off;`, `proxy_request_buffering off;` (parity: Caddy streams request bodies), `proxy_read_timeout 1d;`/`proxy_send_timeout 1d;` (60s default kills quiet WebSocket/SSE).
- Each proxied location repeats the proxy block (`proxy_set_header` only inherits into locations defining none): `proxy_http_version 1.1;`, `Host $bellhop_http_host`, `X-Forwarded-For` *set* to `$remote_addr` (not appended, like Caddy 2.5+ without `trusted_proxies`; clients can't pose as LAN), `X-Forwarded-Proto`/`-Host`/`-Port`, `Upgrade`/`Connection $bellhop_connection_upgrade`. nginx defaults oppose Caddy's on each, which would break backends on switching.
- Backend TLS: `insecureTls` -> `proxy_ssl_verify off;`; port 443 -> `proxy_ssl_verify on;` + `proxy_ssl_trusted_certificate /etc/ssl/certs/ca-certificates.crt;` (without explicit `on`, nginx silently skips verification).

**Forward-auth.** Server level `proxy_buffers 8 16k;`/`proxy_buffer_size 32k;` (Authentik's big headers). `location /` gets Authentik's standalone-nginx recipe, bellhop-prefixed: `auth_request /outpost.goauthentik.io/auth/nginx;`, `error_page 401 = @goauthentik_proxy_signin;`, `Set-Cookie` pass-back, five identity headers. Forward routes always get `location /outpost.goauthentik.io` and `location @goauthentik_proxy_signin`; OIDC/ungated routes get none of this.

Exempt paths: each unique parsed pattern (deduped on kind+path) gets a location with proxy lines and no `auth_request`: exact `location = "<path>"`, prefix `location ^~ "/api/"` (beats operator regex locations, matching Caddy's `path /api/*`); `\`/`"` escaped. Bare `/*` makes no location but strips forward-auth from `location /` (a second `location /` fails `nginx -t`).

Patterns at/under `/outpost.goauthentik.io` are silently skipped (an exact/`^~` location would outrank the outpost passthrough and misroute the `auth_request` subrequest). Guest edits (`parseUnauthenticatedPaths` via `commitGuestEdit`) reject them; `UnauthenticatedPathSchema` accepts them so older/hand-written `bellhop.db` entries stay loadable.

**Certificate.** Every block uses `ctx.tls`, one operator-managed cert (in practice a certbot-renewed wildcard; default path certbot's for the inventory `domain`).

Single-operator assumptions: CA bundle path and `conf.d` default path assume Debian/Ubuntu.

## Nginx Proxy Manager driver (`nginx-proxy-manager.ts`, `src/lib/npm-client.ts`)

No config file: `defaultConfigPath: null` (why `DriverDeps.configPath` is `string | null`); Settings hides Proxy config path, Status page path, TLS fields. `usesNpmApi: true` (#73) shows `npmApiUrl`/`npmApiEmail`/`npmApiPassword` at the end of the Proxy tab. `authModes: ['forward', 'oidc']`, `acmeDns01ViaCloudflare: () => false`, `statusPage: null`. Tested on NPM 2.16 (older releases may reject sent fields).

**`NpmClient`** (`AuthentikClient` pattern): interface, `zod`-validated `RealNpmClient`, `buildNpmClient(inventory)` reading `npmApiEmail`, secret `npmApiPassword`, optional `npmApiUrl` (else the `proxy: true` entry's `ip`, port 81) via the config accessor at call time (`NPM_API_EMAIL`/`NPM_API_PASSWORD`/`NPM_API_URL` override; `Settings store` in `src/lib/CLAUDE.md`). No credential or URL: named error before any request.

- Logs into `/api/tokens` lazily once per `plan()`/`apply()`/`snapshot()` (`clientFor`); never refreshes (one-day token).
- `AbortSignal.timeout(NPM_REQUEST_TIMEOUT_MS)` (10s); `requestCertificate` gets `NPM_CERTIFICATE_TIMEOUT_MS` (180s), as NPM runs certbot synchronously.
- `NpmCertificateSchema` has no `meta`: PEM/private keys drop at parse, never reaching previews, logs, `snapshot()`, or errors.
- Proxy-host fields besides `id`/`domain_names`/`forward_*`/`enabled` have defaults (`false`; `0` for `certificate_id`/`access_list_id`; `''` for `advanced_config`) so older rows parse (owned ones show drift). A `null` `expires_on` is expired.

**Ownership/conflicts.** `isOwned(host)`: `advanced_config` starts with `NPM_OWNERSHIP_MARKER` (`# Managed by Bellhop sync-proxy...`); deleting it hands the host back. `planNpmSync` (pure) matches routes to owned hosts by `hostnames[0]`; an unowned host holding any route name makes a `conflict`. Redirection/404 hosts (`listRedirectionHosts`/`listDeadHosts`; live-verified NPM refuses proxy hosts using their names) are unowned, never written/deleted; conflict lines name the kind (`proxy host #N` / `redirection host #N` / `404 host #N`; ids are per kind). A route's owned host is marked matched *before* the conflict check, so it's never deleted as stale. Matching is lower-cased.

**Update ordering.** NPM rejects a name another host holds (`"<name> is already in use"`), so releases precede claims. `orderUpdates` is a stable topological sort (`x` before `y` when `x`'s *current* names include one of `y`'s *desired*); ties keep route order; a cycle (alias swap) keeps route order and fails on NPM's rejection. Deletes first, creates last.

**Certificates.** `chooseCertificate` keeps the current cert while it covers every hostname and isn't expired; else the qualifying one with latest `expires_on` (lowest id on tie); else `apply()` calls `requestCertificate` (HTTP-01, login email as contact; 2.16 has no `letsencrypt_email`) just before that route's write. Failure throws naming route and NPM error, leaving the existing host (update) or none (create).

**Read-back.** NPM accepts hosts nginx rejects, so each write is re-`GET` and throws if `meta.nginx_online === false`, quoting `meta.nginx_err` and naming id, canonical hostname, and that the site is offline until the next successful sync. `planNpmSync` treats such an owned host as drift even when fields match (pseudo-field `nginx_online`). The first NPM error stops `apply()`; `conflicts` throw only after all other writes, naming all together.

**Rendering.** `desiredProxyHost` passes `renderServerBody` `$http_host`/`$http_connection` (`advanced_config` is inside NPM's `server {}`; `map` is `http {}`-only). Every write sends fixed settings in full (`ssl_forced`/`http2_support`/`allow_websocket_upgrade` on; `block_exploits`/`caching_enabled`/`hsts_*`/`trust_forwarded_proto` off; `access_list_id: 0`; `locations: []`); UI edits revert as drift.

**Tests.** `FakeNpmClient` (`test/support/fake-npm-client.ts`: NPM-style ids, duplicate-hostname rejection, offline writes, failed cert requests). `test/lib/npm-client.test.ts` pins `RealNpmClient` to real NPM 2.16.0 responses in `test/fixtures/nginx-proxy-manager/`, tokens/PEM bodies/loopback addresses replaced, shape unchanged (constitution Principle I).

## HAProxy driver (`haproxy.ts`)

`fileDriver` over **two** `'owned'` files: backends at `configPath` (default `/etc/haproxy/bellhop.cfg`), one `backend` per route; and `mapPath(configPath)` = `bellhop.map` in its POSIX directory (derived), one lower-cased `<hostname> <backend>` line per hostname, canonical first. `render()` throws naming `proxyConfigPath` if the paths coincide once normalised or it ends in `/` (`SettingsSchema` allows that). `ownedHeader` for both is "Generated by Bellhop sync-proxy for HAProxy. Do not edit" (unlike nginx's), so a Caddyfile/nginx file at a shared path is refused. `configFiles()` returns both so `snapshot()` (a contract method) reads both; nothing calls it today, since `statusPage: null`.

**Operator-owned** (`docs/reverse-proxy/haproxy.md`): the `frontend` in `/etc/haproxy/haproxy.cfg` (`bind :443 ssl crt <dir>`, own `default_backend`, `use_backend %[req.hdr(host),field(1,:),lower,map(/etc/haproxy/bellhop.map)]`); `EXTRAOPTS="-S /run/haproxy-master.sock -f /etc/haproxy/bellhop.cfg"` in `/etc/default/haproxy` (`-S` repeats the Debian default it replaces; restart once); certificates. Changing `proxyConfigPath` needs both updated and a restart: documented, not validated.

Validate `haproxy -c -f /etc/haproxy/haproxy.cfg -f '<configPath>'` (backends alone lack frontend/`global`); reload `systemctl reload haproxy`.

- Names `bellhop_<owner.type>_<name>` (`backendNames`), chars outside `[A-Za-z0-9_.:-]` -> `_` (`/`/space fail `haproxy -c`), `_2`, `_3`... in route order on collision; joins the two files.
- Body: `mode http`; `timeout server`/`timeout tunnel 1d` (SSE's client side stays under the frontend's `timeout client`; docs say raise it); first `http-request del-header x-authentik- -m beg` (no backend is forward-gated, so these are spoofed); `X-Forwarded-For` *set* to `%[src]`; `X-Forwarded-Proto https`; `X-Forwarded-Host` original Host; `X-Forwarded-Port` `ctx.externalPort`; one `server app <ip>:<port>`, no `check`.
- TLS: `ssl verify none` (`insecureTls`); `ssl verify required ca-file /etc/ssl/certs/ca-certificates.crt` (443); else plain. Chain only, not name (no `sni`/`verifyhost`): documented, not worked around.

**Auth.** `authModes: ['oidc']`, `acmeDns01ViaCloudflare: () => false`. `checkCapabilities` refuses forward entries; `render()` still throws `HAProxy cannot enforce forward-auth for entry '<name>'` as a backstop so none deploys ungated. `oidc` renders like ungated; no `unauthenticatedPaths`. No `usesSharedCertificate`, so Settings shows only Proxy config path, with a `configPathNote` on the map file and ownership refusal.

Hand-checked with `haproxy -c` on 2.6/3.4 (not in `npm test`).

Single-operator assumptions: `/etc/haproxy/haproxy.cfg`, the CA bundle (shared with nginx), and `systemctl reload haproxy` are fixed Debian/Ubuntu defaults.

## Traefik driver (`traefik.ts`)

`fileDriver` over one `'owned'`, `atomic: true` file (default `/etc/traefik/dynamic/bellhop.yml`), atomic because the file provider watches live. Checked on v3.7.13 (v2 unsupported).

**Rendering.** One `http:` document; `routers`/`services` omitted when empty, `middlewares` always present. Names are `bellhop-`-prefixed, route names via `encodeHostname(canonical)`: lowercase, double every `-`, *then* `.` -> `-` (injective for valid DNS names, e.g. `a.b-c` vs `a-b.c`); labels starting/ending in `-` can collide (`a-.b` vs `a.-b`), so `render()` throws naming both. It also throws (dry run too) with the path and `settingFix` remedy if `proxyConfigPath` ends in `/` or not `.yml`/`.yaml`. `stringify` uses `lineWidth: 0` so rules never fold.

- Per route: router+service `bellhop-route-<enc>`; router `bellhop-exempt-<enc>` (forward-gated, exempt paths left after dropping outpost-namespace ones, no bare `/*`); router `bellhop-outpost-<enc>` (forward-gated).
- Shared: middleware `bellhop-strip-authentik-headers` (always; sets the five `X-authentik-*` to `""`, i.e. remove; first on every router, so spoofed identity headers never reach a backend, even via exempt paths or Bellhop's web UI); `bellhop-forwarded-port` (always; `X-Forwarded-Port: 443` via `customRequestHeaders`); `bellhop-authentik` (if any forward route; after the strip); service `bellhop-authentik-outpost`; `serversTransports` `bellhop-insecure-backend-tls` (`insecureSkipVerify: true`, if needed).
- A forward main router carries `bellhop-authentik` unless exempt patterns include bare `/*`; then that and the exempt router are dropped; the outpost router stays.
- `candidateExemptPatterns` (dedup + outpost skip) and `isRootPrefix` are shared from `nginx-locations.ts`.
- `backendUrl` follows the shared scheme rule; `insecureTls` uses the insecure transport, else the default verifies 443 backends against the system CA pool.

**Rules.** Main `Host(`a`) || Host(`b`)` (canonical first); outpost `(<hosts>) && PathPrefix(`/outpost.goauthentik.io/`)`; exempt `(<hosts>) && (Path(`/x`) || PathPrefix(`/api/`))`, stored order. `ruleValue` backtick-quotes, else `JSON.stringify` if the value has a backtick (live-verified equivalent). No `priority`: Traefik ranks by rule length, and exempt/outpost rules extend the main host expression, so they win.

**Forward-auth.** `bellhop-authentik`: `forwardAuth` at `http://<outpost ip>:<port>/outpost.goauthentik.io/auth/traefik`, `trustForwardHeader: true`, five identity headers (Authentik's recipe).

**Cert resolver.** `tls.certResolver` = `certResolverName(inventory)` = `proxyCertResolver ?? DEFAULT_CERT_RESOLVER` (`'cloudflare'`, `src/lib/proxy/routes.ts`), carried as always-present `ProxyContext.certResolver`. Reserved `NO_CERT_RESOLVER = 'none'` (`routes.ts`, regex-admitted) makes `routerTls(ctx)` render `tls: {}` (file-provider or default cert). `acmeDns01ViaCloudflare: traefikAcmeDns01ViaCloudflare` (resolver `!== NO_CERT_RESOLVER`; any named one may be Cloudflare DNS-01). `authModes: ['forward', 'oidc']`; `statusPage: null` (covered by `statusPageUnsupportedError`/`statusPageSkipReason`).

Traefik-only settings (`usesCertResolver`/`usesApiUrl`): `proxyCertResolver` (`^[A-Za-z0-9_-]+$`, Traefik's rule); `proxyApiUrl` (`new URL`, `http:`/`https:`; the no-single-quote check is only defensive).

**API check (opt-in).** No validate command exists: undecodable YAML is rejected whole; an object-level problem (missing service/middleware, unknown entry point, bad rule) loads the rest and marks that router `"status":"disabled"` with an `"error"` array. `def.validateCommand` is `null` unless `proxyApiUrl` is set; `reloadCommand` is always `null` (live once the rename lands). `buildApiCheck(apiUrl, configPath, content)` builds the POSIX `sh` subshell:

1. `command -v curl`; if missing, fail naming the fix (install curl on the proxy host or unset `proxyApiUrl`).
2. Poll `GET /api/http/middlewares/<marker>@file` (`curl -s -o /dev/null -w '%{http_code}' --max-time 5`, 1/s, up to 30 tries, comfortably above Traefik's default 2-second file-provider throttle) for `200`; the marker name is a SHA-256 of the file rendered without it, proving this version loaded. `generationMarkerName`/`routerNames` parse names back from `content`.
3. `GET /api/http/routers/<name>@file` per router by exact name (`?search=` also matches rule text, catching operator routers), collecting all not `"status":"enabled"` before failing.

On failure `fileDriver`'s trap restores. Tests stub `curl`/`sleep` on `PATH` (instant timeout case).

Known gaps (`docs/reverse-proxy/traefik.md`): the timeout is fixed, and each check can take `--max-time 5`, so the message says "after 30 checks one second apart", never "within 30 seconds"; a router naming an undefined `certResolver` stays `"status":"enabled"` (live-verified; only the log says `Router uses a nonexistent certificate resolver`), so a wrong `proxyCertResolver` isn't caught.

Out of scope: Docker labels, a Bellhop-served HTTP provider, static config; only the file provider's directory is written.

Single-operator assumptions: entry point fixed at `websecure`; unset `proxyCertResolver` means `cloudflare`; the fixed API-check timeout.

## Caddy admin-API driver (`caddy-api.ts`)

`proxyDriver: 'caddy-api'`, label "Caddy (admin API)": the Caddy driver's output, reconciled into Caddy's live JSON config via its admin API. Not `fileDriver`; `defaultConfigPath: null`, so Settings hides Proxy config path but shows Status page path (`/usr/share/caddy/index.html`). Capabilities match Caddy's.

**`src/lib/proxy/caddy-json.ts` (pure).** `renderRoute`; `renderTlsObjects(hostnames, ctx)` -> `{ policy }` (automation) for `cloudflare`/`internal`, `{ loadFile, connectionPolicy }` for `files`, `{}` for `letsencrypt`. `planCaddyConfig` places `renderDefaultConnectionPolicy()` (the adapter's trailing catch-all), as need depends on the live server. Parity with `caddy adapt` of `caddy.test.ts`'s characterization block is pinned per mode by `test/fixtures/caddy/{characterization,tls-internal,tls-files,tls-letsencrypt}-adapted.json` (Caddy v2.10.2).

**`planCaddyConfig(current, routes, ctx, host)`.**

- Bellhop `@id`s start `bellhop-`: `bellhop-route-<canonical hostname>`; per mode `bellhop-tls` (automation policy; `cloudflare`/`internal`), and in `files` only: `bellhop-tls-files` (`load_files` entry, cert tagged `bellhop-cert` not `cert0`), `bellhop-tls-connection` (SNI policy selecting that tag), `bellhop-tls-default` (catch-all, only if the server has no untagged catch-all). Untagged objects are never changed.
- Routes are prepended to the single server on 443 (empty config gets `srv0` on `:443`; zero or several HTTPS servers throws naming them). The policy is prepended to `apps.tls.automation.policies` and removed when no route remains (empty `subjects` would match everything); `files` objects are pruned likewise.
- `CaddyConflict` (route left out): an untagged route naming an inventory hostname exactly (case-insensitive; not wildcards), always; an untagged automation policy naming one, only in `cloudflare`/`internal` (otherwise Bellhop writes no policy and an operator catch-all should apply).
- Key-order-insensitive comparison (`canonicalJson`; Caddy sorts keys): no change plans `config: null`, writing nothing.

**`src/lib/proxy/caddy-admin.ts` (POSIX `sh` via `runRemote`).**

- `readCaddyConfig`: `curl -sS -D - http://localhost:2019/config/`, parses `Etag`, passthrough zod schema. A sync (not `snapshot()`/`convert-caddyfile`) first runs `systemctl is-active --quiet caddy.service`; exit 3 -> the "running from a Caddyfile" refusal (`systemctl reload caddy` would discard API changes).
- `writeCaddyConfig`: compact JSON in a quoted heredoc, one `PATCH /config/` + `If-Match: <etag>`. Live-verified on v2.10.2: `PATCH /config/` honors `If-Match` (412 when stale, nothing written); `POST /load` ignores it; an unprovisionable config gets 500 with the old config still running.
- `apply()` writes the non-conflicting config, then throws one line per conflict. `snapshot()` pretty-prints `GET /config/`.

**`convert-caddyfile [--caddyfile <path>] [--apply]`** (`src/commands/networking/convert-caddyfile.ts`, CLI-only, one-time): `caddy adapt`s a copy of the Caddyfile minus the managed block, placed *beside* it so relative `import`s resolve; adds routes via the same planner; `PATCH`es against the live `Etag` while `caddy.service` runs (Caddy autosaves; `caddy-api.service`'s `--resume` loads it). Refuses once a `bellhop-` object is live.

**Limit.** A guest proxy host gets the config as one `sh -c` argument via `pct exec`, so Linux's 128 KiB single-argument limit applies (documented in `docs/reverse-proxy/caddy-api.md`, not engineered around).

Single-operator assumptions: admin address `localhost:2019` on the `proxy: true` entry; systemd packaged unit names (`caddy.service` checked, `caddy-api.service` documented); `curl` on the proxy host; `cloudflare` mode's fixed `ACME_DNS_RESOLVERS`.
