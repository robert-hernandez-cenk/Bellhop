# Data model: MCP over HTTPS

All new persistent state lives in `data/sessions.sqlite3` (opened by `SessionStore`), never in `inventory/bellhop.db`'s full-replace tables. Every token-like value is stored as its SHA-256 hex hash; the raw value exists only in the response that hands it out. Times are epoch ms from the store's injected clock.

## Existing tables, changed

### `sessions` (from #69)

Unchanged schema. An MCP sign-in creates an ordinary row through `SessionService.create`; its raw id is hashed and discarded at once, so no cookie can ever name it. Its 30-day life bounds the grant that references it.

### `login_attempts` (from #69)

| Column | Change |
|---|---|
| `mcp_pending_hash TEXT NULL` | new (`ensureColumn`). Set when the attempt was started by MCP consent; the callback then finishes an MCP authorization instead of setting a cookie. |

## State transitions

```
register ─► client
/authorize ─► pending ──deny──► (client gets access_denied)
                │approve
                ▼
       login attempt (mcp_pending_hash) ─► Authentik ─► /auth/callback
                │ non-admin → page, session deleted, nothing issued
                ▼ admin
       session row + code ─► POST /token (PKCE) ─► grant + access + refresh
       refresh ─► new access + rotated refresh (old refresh dead)
       request ─► access → grant → session (re-check ≤5 min) → admin? → MCP
       revoke / session gone ─► grant + its access tokens deleted
```

## In-memory

### MCP HTTP session (`McpHttpHost`)

`{ transport, server, principal, username, lastSeen }` keyed by `Mcp-Session-Id`; idle 30 min → closed. One shared `PromptTracker`.
