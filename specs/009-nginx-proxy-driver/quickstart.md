# Quickstart: validating the nginx driver

All commands run from the worktree root. Nothing here touches real
infrastructure except the optional live check at the end.

## 1. Automated checks

```bash
npm run typecheck
npm test
npm run web:build
```

The nginx driver's own tests live in `test/lib/proxy/drivers/nginx.test.ts`
(render output per contracts/nginx-config.md, plus the executed-script
restore test). Settings round trips are in `test/commands/set-config.test.ts`
and `test/web/routes/settings.test.ts`; `test/lib/proxy/drivers/caddy.test.ts`
must still pass unchanged (FR-013).

## 2. Dry run against an example inventory

```bash
INVENTORY_DIR="$(mktemp -d)"
npm run bellhop -- import-yaml-inventory \
  --yaml-path inventory/hosts.yaml.example \
  --db-path "$INVENTORY_DIR/bellhop.db" --apply
export INVENTORY_FILE="$INVENTORY_DIR/bellhop.db"

npm run bellhop -- set-config proxyDriver nginx --apply
npm run bellhop -- sync-proxy
```

Expected: the preview starts with the "Generated by Bellhop" header and the
two `map` blocks, then one `server` block per example entry with
subdomains, using `/etc/letsencrypt/live/<example domain>/...` certificate
paths. (`sync-proxy` without `--apply` makes no SSH call for a file driver's
preview.)

```bash
npm run bellhop -- set-config proxyTlsCertificate /etc/ssl/example/fullchain.pem --apply
npm run bellhop -- set-config proxyTlsKey /etc/ssl/example/privkey.pem --apply
npm run bellhop -- sync-proxy
npm run bellhop -- set-config proxyTlsKey relative/path --apply   # rejected: must be an absolute path
```

Expected: every `ssl_certificate`/`ssl_certificate_key` line now names the
configured paths; the relative path is refused.

## 3. Settings page

`npm run web:dev`, open `/settings` as an admin, and confirm the Proxy TLS
certificate and Proxy TLS key fields save, clear, and reject a relative
path with the same message as `set-config`. Check at desktop width and at
≤640px.

## 4. Optional live check (operator, real nginx host)

On a proxy host with nginx and a wildcard certificate at certbot's default
location: `set-config proxyDriver nginx --apply`, `sync-proxy`, then
`sync-proxy --apply`. Confirm `nginx -t` passed, each site answers over
HTTPS, a forward-gated site redirects to Authentik and back, and an exempt
path is reachable signed out. Not run as part of this change: the
deployment's proxy runs Caddy.
