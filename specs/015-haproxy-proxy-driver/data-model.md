# Data Model: HAProxy Proxy Driver

No inventory schema or settings change. `proxyDriver` accepts one more
value, `haproxy`, because its zod enum is built from `PROXY_DRIVER_IDS`.

## haproxyDriver (ReverseProxyDriver)

| Field | Value |
| --- | --- |
| `id` | `'haproxy'` |
| `label` | `'HAProxy'` |
| `capabilities` | `{ authModes: ['oidc'], acmeDns01ViaCloudflare: false }` |
| `defaultConfigPath` | `'/etc/haproxy/bellhop.cfg'` |
| `statusPage` | `null` |
| `usesSharedCertificate` | not set (false) |
| `configPathNote` | "HAProxy replaces this whole file and writes bellhop.map beside it on every apply, and refuses to replace a file it didn't generate." |
| validate | `haproxy -c -f /etc/haproxy/haproxy.cfg -f <configPath>` (configPath single-quoted) |
| reload | `systemctl reload haproxy` |
| `configFiles(configPath)` | `[configPath, mapPath(configPath)]` |

Registry order (`listDrivers()`): Caddy, nginx, Nginx Proxy Manager,
HAProxy, No proxy.

## FileSpec outputs of render()

Both `mode: 'owned'`, each with `ownedHeader` equal to its first line.

| File | Path | Header |
| --- | --- | --- |
| Backends | `configPath` | `# Generated by Bellhop sync-proxy for HAProxy. Do not edit: this file is replaced on every apply.` |
| Map | `mapPath(configPath)` | same header text |

The header names HAProxy so it differs from the nginx driver's own header;
otherwise the ownership check could not tell an nginx-generated file left at
a shared `proxyConfigPath` from one of this driver's.

## Backend name

Derived per route (research R3): `bellhop_<owner.type>_<sanitised name>`
with `_2`, `_3`, … suffixes on collision in route order. The join key
between the map file's second column and the backends file's `backend`
lines.

## Validation rules

- `configPath` must not end in `/`, else `render()` throws naming
  `proxyConfigPath` (`SettingsSchema` only requires an absolute path).
- `mapPath(configPath) !== posix.normalize(configPath)`, else `render()`
  throws naming `proxyConfigPath`.
- Every route in `plan()` input has `auth.mode` `ungated` or `oidc`;
  forward-mode routes never reach `render()` because `runSyncProxy` throws
  on the capability errors first (and, since this driver has no forward
  mode, calls `buildRoutes` with `requireOutpost: false`, so a missing
  `authentik: true` entry never pre-empts that refusal). `render()` still throws on a forward
  route (naming the entry) as a backstop, so a caller that skipped the
  capability check can never emit a forward-gated route ungated.
