# Contract: HAProxy driver output

Exact text `render()` produces. `H` stands for the header line
`# Generated by Bellhop sync-proxy for HAProxy. Do not edit: this file is replaced on every apply.`
It names HAProxy so it differs from the nginx driver's header: the header is
each file's `ownedHeader`, and an apply refuses to replace an existing file
whose first line isn't it — including a file the nginx driver generated.

## Backends file (`configPath`)

```
H
<blank line, then one backend block per route, blocks separated by a blank line>
```

With zero routes the file is the header line alone.

### Backend block

```
backend <backendName>
    mode http
    timeout server 1d
    timeout tunnel 1d
    http-request del-header x-authentik- -m beg
    http-request set-header X-Forwarded-For %[src]
    http-request set-header X-Forwarded-Proto https
    http-request set-header X-Forwarded-Host %[req.hdr(host)]
    http-request set-header X-Forwarded-Port <ctx.externalPort>
    server app <backend.ip>:<backend.port><tls>
```

The `del-header` line is always the first `http-request` rule: no Bellhop
HAProxy backend is ever behind forward-auth, so any `X-authentik-*` header
reaching one is client-supplied and is stripped (research R5).

`timeout tunnel 1d` covers an upgraded WebSocket on both sides. A quiet
server-sent-events stream is plain HTTP, so its client side stays under the
operator frontend's own `timeout client` (research R5).

`<tls>`:

| Condition | Suffix |
| --- | --- |
| `backend.insecureTls` | ` ssl verify none` |
| `backend.port === 443`, not insecure | ` ssl verify required ca-file /etc/ssl/certs/ca-certificates.crt` |
| otherwise | *(nothing)* |

`auth.mode` `ungated` and `oidc` render identically. `unauthenticatedPaths`
never appear. A `forward` route makes `render()` throw:
`HAProxy cannot enforce forward-auth for entry '<name>'` (backstop only —
`checkCapabilities` refuses it first with the standard message, even with
no `authentik: true` entry, since `runSyncProxy` passes
`requireOutpost: false` to `buildRoutes` for a driver without forward-auth).

`render()` also throws, naming `proxyConfigPath`, when `configPath` ends in
`/` (it must name a file) or normalises (`posix.normalize`) to the map path
itself.

## Map file (`<dirname(configPath)>/bellhop.map`)

```
H
<hostname> <backendName>        one line per hostname, routes in order,
                                each route's hostnames canonical first,
                                hostname lower-cased
```

With zero routes the file is the header line alone.

## Example

Inventory: domain `example.com`; guest `web-lxc` (`192.0.2.10:8080`,
subdomains `web`, `www`); host `pve1` (`192.0.2.2:8006`, `insecureBackendTls`,
subdomain `pve`); external site `nas` (`192.0.2.20:443`, OIDC-gated,
subdomain `nas`).

`/etc/haproxy/bellhop.cfg`:

```
# Generated by Bellhop sync-proxy for HAProxy. Do not edit: this file is replaced on every apply.

backend bellhop_host_pve1
    mode http
    timeout server 1d
    timeout tunnel 1d
    http-request del-header x-authentik- -m beg
    http-request set-header X-Forwarded-For %[src]
    http-request set-header X-Forwarded-Proto https
    http-request set-header X-Forwarded-Host %[req.hdr(host)]
    http-request set-header X-Forwarded-Port 443
    server app 192.0.2.2:8006 ssl verify none

backend bellhop_guest_web-lxc
    ...
    server app 192.0.2.10:8080

backend bellhop_externalSite_nas
    ...
    server app 192.0.2.20:443 ssl verify required ca-file /etc/ssl/certs/ca-certificates.crt
```

`/etc/haproxy/bellhop.map`:

```
# Generated by Bellhop sync-proxy for HAProxy. Do not edit: this file is replaced on every apply.
pve.example.com bellhop_host_pve1
web.example.com bellhop_guest_web-lxc
www.example.com bellhop_guest_web-lxc
nas.example.com bellhop_externalSite_nas
```

## Dry-run preview

`fileDriver`'s `plan()` labels each file of a multi-file preview with the
`==> <path> <==` line `snapshot()` uses, files separated by a blank line:

```
==> /etc/haproxy/bellhop.cfg <==
<backends file>

==> /etc/haproxy/bellhop.map <==
<map file>
```

The payload `apply()` writes carries each file's content unlabelled. A
single-file driver's preview is its file's content alone, unchanged.

## Apply

`fileDriver`'s script over both files (in the order backends, map), then:

- validate: `haproxy -c -f /etc/haproxy/haproxy.cfg -f '<configPath>'`
- reload: `systemctl reload haproxy`

## Operator-side prerequisite (documented, not generated)

```
frontend https
    bind :443 ssl crt /etc/haproxy/certs/
    use_backend %[req.hdr(host),field(1,:),lower,map(/etc/haproxy/bellhop.map)]
    default_backend <operator's own>
```

and `EXTRAOPTS="-S /run/haproxy-master.sock -f /etc/haproxy/bellhop.cfg"` in
`/etc/default/haproxy` — the `-S` keeps the Debian unit's own default
`EXTRAOPTS` (its master socket), which this file overrides, and a
`systemctl restart haproxy` is needed after first editing it (a reload keeps
the original command line). The validate command checks the main
configuration plus `configPath`, but the running service loads whatever
`EXTRAOPTS` names and the frontend reads whatever `map()` path it names, so
changing `proxyConfigPath` means updating both (and restarting).
