# Data Model: Traefik Proxy Driver

## Settings (inventory `meta` table, `SettingsSchema`)

| Key | Type / rule | Default when unset | Read by |
| --- | --- | --- | --- |
| `proxyCertResolver` | string, `^[A-Za-z0-9_-]+$` | `cloudflare` | `buildProxyContext` -> `ctx.certResolver` |
| `proxyApiUrl` | `http(s)://` URL (no `'`) | no API check | Traefik driver's validate step |

Both are ordinary optional `SettingsSchema` keys, so `SETTINGS_KEYS`,
`saveInventory`'s meta upsert/delete, `set-config` and `PATCH
/api/settings` pick them up with no extra plumbing. Both are inert for
every driver except Traefik.

## ProxyContext (extended)

```ts
interface ProxyContext {
  outpost?: { ip: string; port: number };
  externalPort: number;
  tls: { certificatePath: string; keyPath: string };
  certResolver: string; // new: inventory.proxyCertResolver ?? 'cloudflare'
}
```

## ReverseProxyDriver (extended metadata)

| Field | Meaning |
| --- | --- |
| `usesCertResolver?: boolean` | Settings page shows `proxyCertResolver` (Traefik only) |
| `usesApiUrl?: boolean` | Settings page shows `proxyApiUrl` (Traefik only) |

Both are optional and default to false, exactly like `usesSharedCertificate`.
They surface in `GET/PATCH /api/settings`'s `proxyDrivers[]` as required
booleans, and in `proxyFieldView` as `showCertResolverField` and
`showApiUrlField`.

## FileSpec (extended)

```ts
interface FileSpec {
  path: string;
  content: string;
  mode: 'owned' | 'managed-section';
  ownedHeader?: string;

```

## fileDriver definition (extended)

| Field | Before | After |
| --- | --- | --- |
| `validateCommand` | `(configPath) => string` | `(configPath, { files, inventory }) => string \| null`; `null` means no validate step |
| `validateLabel` | none | optional string used in the failure message instead of the command text |
| `reloadCommand` | `string` | `string \| null`; `null` means no reload line |

`buildFileDriverScript(files, validateCommand, reloadCommand, validateLabel?)`
accepts `null` for either command. With `null` validation the script has no
validate block. With a `null` reload, the trap disarm and backup cleanup
are its last lines. Caddy and nginx pass exactly what they passed before,
so their scripts are unchanged.

## Traefik dynamic-configuration file (rendered)

```text
# Generated by Bellhop sync-proxy. Do not edit: this file is replaced on every apply.
http:
  routers:        bellhop-route-<enc> / bellhop-outpost-<enc> / bellhop-exempt-<enc>
  services:       bellhop-route-<enc>, bellhop-authentik-outpost (if any forward route)
  middlewares:    bellhop-forwarded-port (always), bellhop-authentik (if any forward route),
                  bellhop-generation-<hash> (always, last)
  serversTransports: bellhop-insecure-backend-tls (if any insecureTls route)
```

- `<enc>` is the canonical hostname, lowercased, with `-` becoming `--`
  and then `.` becoming `-` (research R7).
- `<hash>` is the first 12 hex characters of the SHA-256 of the file
  rendered without the marker (research R3).
- The marker is a `headers` middleware setting `X-Bellhop-Generation: <hash>`.
- Routes are in `buildRoutes` order; within a route, the keys are in the
  order route, outpost, exempt.
